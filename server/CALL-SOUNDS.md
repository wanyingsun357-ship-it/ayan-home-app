# Call sound hints: first native version

This is the first, small-category implementation of the user-approved tutorial at https://ariaduet.pages.dev/ai-hears-your-body/ . It uses the tutorial's Apple SoundAnalysis alternative, not a converted YAMNet model. The five allowlisted categories are laughter, breathing, sigh, gasp and crying. Their aliases were verified against Apple's actual built-in classifier on the macOS compile runner; this does not establish phone microphone recognition accuracy.

The native audio tap and existing 16 kHz PCM path remain shared with ASR. `CallSoundAnalyzer` analyzes float PCM only on its bounded utility queue. It opens no second audio device and writes no recording. A one-second analysis window overlaps by 50%; `CallSoundPolicy` requires two successive matching windows and a four-second local cooldown. Only labels actually advertised by the system classifier are enabled. See Apple's classifier guide: https://developer.apple.com/videos/play/wwdc2021/10036/ and `knownClassifications`: https://developer.apple.com/documentation/soundanalysis/snclassifysoundrequest/knownclassifications .

The first-run preference defaults to off in UserDefaults. Native capability detection keeps Build 43 and browser calls working; the new native build is needed for sensing. Mute/typing, audio deactivation, counterpart playback, off and call end invalidate the analyzer generation, cancel in-flight sound requests and reset partial classifications. Playback adds a short settle delay before sensing resumes. ASR reconnects do not grant permission to unmute or start sensing.

`/api/native-call/sound-setting` and `/sound` use the existing call-scoped bearer credential. A monotonic per-call setting revision prevents reordered on/off requests or stale observations from re-enabling detection. Requests carry only a generated event ID, allowlisted category, confidence and revision. Arbitrary text/audio/URLs are not passed through. Settings do not bypass device/call authentication.

`call-sounds.cjs` batches for 1.2 seconds, cools each category down for eight seconds, and allows at most two category hints per model reply (sentence entries share one turnId), resetting after 40 seconds of silence. Busy replies defer processing; hints older than 12 seconds expire. Off, pause and call end cancel pending hints. The bridge adapter sends the bounded observation to that call's existing session using the current English-plus-ZH rules; it is labelled as a possibly incorrect observation, not speech, an emotional conclusion or a device command. Only successfully enqueued hints are added to `call.sounds` and published. Speech entries, spoken TTS and call sentence counts remain separate.

Web displays the native switch and state, merges native state/SSE hints by event ID, and shows the same notes in call history. No raw recording is uploaded or retained by this feature, and no seven-day recording collection is enabled. Thresholds need real-device calibration and the feature is not a promise of exact sound identification. Water, vibration, custom moan heuristics, YAMNet conversion and all other tutorial extensions are future work, not implemented here.

Verification: `node --test server/call-sounds.test.cjs`; `node server/native-calls.test.cjs`; existing call-stream tests. Set `AYAN_CALL_BRIDGE_SOURCE` to the privately patched bridge for the VM adapter tests (no production/model requests). The native check workflow runs `swiftc ios/App/App/CallSoundPolicy.swift tests/call-sound/main.swift -framework SoundAnalysis` plus Xcode simulator compilation. Private bridge baselines, credentials and call recordings must not be committed; only the narrow integration patch belongs here.
