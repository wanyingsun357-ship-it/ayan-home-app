# Sentence streaming for calls

The reference call guide describes line-by-line SSE and queuing the first sentence without waiting for the model turn: https://ariaduet.pages.dev/ai-voice-call/ . Our bilingual variant commits each complete `English.[ZH]中文。[/ZH]` pair as an ordinary call entry. `CALL_RULES` asks for one pair per line. Chinese remains the primary caption; only English, including its voice direction tags, goes to TTS.

`call-stream.cjs` is the shared parser and publisher. `call-stream-integration.patch` is a narrow patch against the matching private bridge baseline; do not apply it blindly to a different bridge version. Deployment receipts retain baseline/candidate hashes privately. Do not commit the whole bridge, credentials, calls or transcripts here.

Both browser SSE and the installed native Build 43 consume the same sentence entries. Native uses its existing authenticated state polling (1.2 seconds) and `entryTime` audio endpoint; no new Swift/PushKit behavior is introduced. Captions and queued speech can appear before model completion; audio still waits for per-sentence synthesis. This does not promise character-by-character Chinese translation or eliminate model/network/TTS latency. If the model groups several sentences into one translation, split only when both language sentence counts match; otherwise preserve the bilingual group rather than guess a translation alignment.

Within a turn, slot plus English text identifies issued sentences across repeated cumulative chunks and stream resets. Entry timestamps increase monotonically to preserve existing native/browser replay protection. Repeated wording at different slots or on a new turn is retained. Already issued speech cannot be withdrawn by a later model rewrite. Finalization adds remaining text once, attaches reasoning to the sentence records and sends `reply-done`; the browser waits for queued speech before a remote hangup. Native uses existing `hangupPending`. SSE loss is reconciled by existing polling; installed native authorization remains scoped to the individual call.

Run `node --test server/call-stream.test.cjs` and `node server/native-calls.test.cjs`. To verify the actual integration functions without starting production or requesting a model, set `AYAN_CALL_BRIDGE_SOURCE` to the privately patched bridge file; the additional VM integration test then runs entirely on synthetic sessions/calls. No historical calls are migrated or rewritten.
